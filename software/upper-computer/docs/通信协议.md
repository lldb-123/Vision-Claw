# 智能分拣串口协议 v1

上位机决定目标物体和盒号，STM32 执行整个机械分拣动作。先实现 HELLO、STATUS、HOME，再实现 SORT、RESULT 和运动中可响应的 STOP。

## 物理与帧格式

- UART 115200，8N1，无流控；上位机经 USB 转 TTL 连接。接口电平以实际板卡说明为准，清单中的模块为 3.3V。
- ASCII 文本：`@1,SESSION,SEQ,CMD,ARG1,ARG2...*CCCC\r\n`。
- SESSION：八位大写十六进制；SEQ：1～2147483647 的十进制整数，每个新请求递增，无前导零。
- 命令和参数仅用 ASCII 字母、数字及 `_ . : + -`，不允许逗号、星号、@ 或换行出现在字段内部。
- 帧总长最大 256 字节（包括起止符）。参数不存在时不加尾随逗号。
- CRC-16/CCITT-FALSE：poly=0x1021，init=0xFFFF，refin=false，refout=false，xorout=0。覆盖 @ 之后到 * 之前的原始 ASCII 字节；CRC 输出四位大写十六进制。
- 校验向量：ASCII `123456789` → `29B1`。
- 接收端按字节流累计，不能把一次 UART 回调当成完整一帧。遇到新 @ 重新开始；坏 CRC、超长帧丢弃，不执行动作。

## 坐标与任务含义

`SORT,x,y,bin` 的 x、y 是有符号整数，单位 0.01mm；12500 表示 125mm。传输单位不代表实际定位精度。bin 为 1～6。

当前标定定义托盘左下角为 (0,0)，X 向右，Y 向上。STM32 应接受这个托盘坐标系，再换算到机构坐标。x、y 表示物体参考中心；拨板与物体的接触偏移、避障路径及升降动作由 STM32 同学结合结构实现。实际路径未设计前先用空载或单个物体联调。

## 命令和对应回复

表中均省略公共帧头及 CRC；回复的 SESSION、SEQ 必须与原请求相同。

| 请求 | 正常回复 | 语义 |
|---|---|---|
| HELLO | DONE,HELLO,boot_id,state,homed | 建立会话；返回启动标识、状态、回零标志 |
| STATUS | STATUS,state,active_id,homed,boot_id | active_id=0 表示没有正在执行的运动任务 |
| HOME | ACK,HOME → DONE,HOME | 回原点期间也要继续处理串口 |
| SORT,x,y,bin | ACK,SORT → DONE,SORT,ENTRY_VERIFIED | 完成动作且按约定判据确认入盒 |
| RESULT,target_id | RESULT,target_id,原回复类型,原回复参数... | 查询本会话某个运动任务的最新状态 |
| STOP | DONE,STOP | 中断运动并返回停止完成；无需先 ACK |
| CLEAR_FAULT | DONE,CLEAR_FAULT | 条件允许时清除故障；不自动继续旧动作 |

状态：UNHOMED、IDLE、RUNNING、FAULT。homed 为 0 或 1；boot_id 为每次 MCU 启动改变的八位十六进制标识。

RESULT 示例：

```text
RESULT,12,ACK,SORT
RESULT,12,DONE,SORT,ENTRY_VERIFIED
RESULT,12,ERR,SORT,FAILED,DROP_TIMEOUT
RESULT,12,UNKNOWN
```

动作执行完但入盒无法验证时，可以回复 `DONE,SORT,UNVERIFIED`；上位机会停止推进，不计成功。仅靠脉冲发完不能声明 ENTRY_VERIFIED。光电传感器遮挡一次只说明物体经过，该标志的完整判据要结合盒子到位、物体通过及最终存储状态共同确定。

错误回复为 `ERR,原命令,阶段,错误码`。阶段 REJECTED 表示未接受且未启动动作，FAILED 表示接受后失败。错误码包括 BUSY、NOT_HOMED、OUT_OF_RANGE、BAD_COMMAND、BAD_ARGUMENT、ID_CONFLICT、STALE_ID、SESSION_MISMATCH、FAULT_ACTIVE、DROP_TIMEOUT、ABORTED。

## 重发和停止

上位机默认 300ms 未收到 ACK 则用原编号重发，最多重发两次。已接受的运动任务以独立动作时限等待，期间每 0.5 秒查询 STATUS 和 RESULT，以恢复丢失的完成报文。

STM32 必须按 (SESSION, SEQ) 去重：相同编号、相同内容返回已缓存状态或最终结果，不能再移动一次；同编号不同内容返回 ID_CONFLICT。缓存被清理的旧编号只能返回 STALE_ID 或 UNKNOWN，不能重新执行。模拟器为方便阅读保留整个会话的记录；固件可只保留运动任务记录并用编号高水位拒绝旧请求。

一个时刻只接受一个 HOME 或 SORT；STATUS、RESULT、STOP 在运动期间仍可处理。STOP 使原运动任务得到 `ERR,原命令,FAILED,ABORTED`，自身返回 DONE,STOP。中断后若位置不可信，homed 必须置 0；当前客户端会要求再次回原点。

新会话不能接管正在运动的旧会话：忙时拒绝新 HELLO。HELLO 只建立通信，不清空物理盒子，不代表物体状态已恢复。启动标识变化或结果未知时，上位机不自动重做 SORT。

## 可直接对照的完整帧

下面的 `\r\n` 表示两个实际字节 0x0D、0x0A，不能发送反斜杠字符。

```text
@1,7A1C9E20,12,SORT,12500,8000,2*49A9\r\n
@1,7A1C9E20,12,ACK,SORT*4C23\r\n
@1,7A1C9E20,12,DONE,SORT,ENTRY_VERIFIED*8F2E\r\n
@1,7A1C9E20,12,ERR,SORT,FAILED,DROP_TIMEOUT*1C2B\r\n
```

运行 `python -m unittest discover -s tests -v` 可检查协议基准。`sorting_app/simulator.py` 是可读参考实现；不要求把 Python 逐行翻译为 C，固件只要保持报文和状态语义一致即可。
