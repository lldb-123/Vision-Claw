# 开发接入顺序

先用现有模拟演示理解数据流，再分别替换图像识别和设备传输。核心流程保持为：拍照 → 识别目标 → 确定盒号 → SORT → 验证结果 → 显示 → 下一次拍照。

## 你的开发入口

1. 阅读 `vision.py` 中 Detection 和 BasicDetector。后续识别器实现 `detect(image) -> list[Detection]`，就能接入同一个调度器。
2. Detection.center 是像素坐标，bbox 是 (x,y,w,h)。shape 应给真实类别，例如 cube、cylinder、cone；只有经过验证的真实形状预测才设置 shape_verified=True。
3. surface 是信息类型，可选 none、stain、defect、text、qr 等；surface_value 存文字内容、二维码内容或实际分类所需标识。看不到或无法确定时保持 unknown。分类口径确认后可修改 Detection.category。
4. 在 GUI 创建 detector 的位置替换识别器；命令行同样替换。先用照片集验证，再接相机。
5. `engine.py` 维护类别到盒号的映射和每盒数量。演示只按颜色和轮廓分组；真实流程按颜色、形状、表面类型和表面值分组。六个盒分完后遇到新类会停止，避免混装。

## 队友需要实现什么

STM32 负责回零、坐标到步数转换、拨板偏移与路径、转盘对位、速度与加减速、限位和入盒判据。用户程序只发送物体位置和盒号。先对接 `docs/通信协议.md`，建议把模拟器产生的帧用于串口助手联调。

HAL 的具体串口接收方式由 STM32 型号决定；轮询、接收中断或 DMA 均可。无论选哪种方式，运动期间都要持续处理 STOP、STATUS、RESULT，不能用长时间阻塞延时占满主循环。

## 要补齐的实物信息

- 各电机和舵机对应的机构，托盘坐标与机械原点关系。
- 托盘实际宽高、相机安装方式、图像分辨率与物体高度变化。
- 实物图片，特别是二维码、文字、污渍和缺陷的位置、可见性及分类口径。
- STM32 型号、串口口号、相机编号以及落料反馈定义。

目前排序以画面左下方为优先候选，不声称该顺序能保证无碰撞。是否可推送及推送路径需要下位机结合拨板外形和邻近物体验证；复杂拥挤场景可能需要将障碍物轮廓/规划结果增加到协议后续版本。

## 联调验收

先完成单个物体、固定位置、固定盒号的真实全流程；再增加不同位置、多个类别、随机摆放和失败恢复。记录成功/失败样本、落点偏差及每件耗时，用这些结果决定下一步是否需要模型、额外视角或机构调整。

本版仅实现 Windows 本机界面和协议原型，未做真实 STM32 固件、训练数据集、三维识别模型、实物避障和断电续赛。香橙派部署时需要另行验证 Linux 相机、串口权限和显示环境；无显示器也可先运行命令行模拟。
