# 智能分拣上位机

这是工创赛智能分拣的第一版 Python 工程。你负责视觉、通信和上位机流程；队友实现 STM32 固件、运动控制和传感器反馈。

程序默认启动模拟演示：从合成图片识别 12 个彩色图形，经真实格式的串口报文驱动模拟 STM32，分入 6 个盒子并逐件更新显示。模拟器与真实串口共用同一个通信客户端。

## 现在怎么运行

首次克隆先在本目录运行 **一键安装环境.cmd**，再双击 **启动程序.cmd**，点击 **自动运行**。也可以点击“只处理一件”观察一轮通信。

本目录使用独立 `.venv`，虚拟环境不提交到 Git。安装脚本会按 `requirements.txt` 创建本机环境，不需要复制原桌面虚拟环境。

换到另一台 Windows 电脑时，先安装 Python 3.11 或更新版本，再双击 **一键安装环境.cmd**。不要复制 `.venv` 到另一台电脑；只复制源代码、配置、文档和启动脚本，重新创建环境。

命令行（在本目录打开 PowerShell）：

```powershell
.\.venv\Scripts\python.exe -m sorting_app
.\.venv\Scripts\python.exe -m sorting_app --headless
.\.venv\Scripts\python.exe -m sorting_app --headless --drop-first-ack
.\.venv\Scripts\python.exe -m sorting_app --image "D:\照片\托盘.jpg"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## 已有功能

- 中文桌面控制台：托盘画面、六个盒子的数量、最近物体图片、逐件结果和通信记录。
- 图片导入、USB 相机拍照、颜色分割与二维轮廓定位。
- 点击四个托盘角点，保存平面坐标标定。
- 文本串口协议、CRC 校验、拆包/粘包、同编号重试、结果查询、软件停止。
- 模拟 STM32：正常动作、丢失 ACK、丢失完成回复、落料失败等。
- 完整分拣调度、类别到盒号的映射、已验证结果计数、逐件 JSONL 日志。

## 识别能力的实际范围

当前 BasicDetector 识别红、绿、蓝、黄等饱和颜色和圆形、方形、三角形、多边形的二维轮廓。适合先验证清晰、分离的彩色物体。黑白、低饱和颜色、强反光、粘连、遮挡等尚未处理。

圆形轮廓不等于圆柱或圆锥。代码没有把二维轮廓伪装成立体形状预测，也没有实现污渍、缺陷、文字或二维码识别。表面信息目前返回 `unknown`。因此，真实图片现在可以分析；真实自动分拣需接入经过实物验证的识别器。演示中的六类只用于测试流程，实际类别由识别输出动态分配，不固定为队伍草稿的六类。

## 工程结构

```text
sorting_app/
  protocol.py    报文与 CRC；最适合和 STM32 同学一起看
  transport.py   pySerial 串口适配
  simulator.py   模拟 STM32，可用作固件协议逻辑参考
  client.py      ACK、结果查询、重试、停止与重启检测
  vision.py      图像输入、基础识别、坐标标定、演示场景
  engine.py      一次一件的主流程、盒号分配与计数
  gui.py         中文控制台
  __main__.py    界面和命令行入口
configs/default.json       可调整参数
docs/通信协议.md           发给 STM32 同学对接
docs/开发接入.md           你的下一步开发入口
tests/test_system.py       关键协议与流程测试
logs/                      运行时生成的逐件结果
```

## 接真实设备

1. 先和 STM32 同学商议接口，再实现固件或调整上位机。`docs/通信协议.md` 是当前演示提案；仓库中的队友电控初版使用另一套命令，还不能直接互通。电机距离换算、拨板参考点、路径、转盘到位和落料反馈都由正式固件负责。
2. 修改 `configs/default.json` 的串口、相机编号与实际托盘尺寸。在界面填写串口号，点击“连接 STM32”，先联调状态查询、回原点和停止。
3. 用“相机拍照”获取图像，按左上、右上、右下、左下选择真实托盘四角。文件保存到 `configs/calibration.json`。用已知坐标的实测点核对位置误差。
4. 替换 `BasicDetector`，提供真实形状和表面属性，再联调单个物体的 SORT。

默认托盘尺寸 260×260mm、动作超时 12 秒、相机分辨率等均为开发参数，须按实物修改。演示设备坐标范围固定为 0～260mm，正式固件自行校验实际行程。

标定仅适用于同一固定相机及参考平面。摄像头移动、镜头畸变或物体高度会影响位置，需要按实物进一步处理；分辨率变化需重新标定。

静态照片用于分析，不会反复将同一张照片中的物体当成新物体分拣。界面会阻止合成画面驱动真实设备。软件 STOP 由 STM32 执行，不能替代硬件急停。

默认本轮计时从首次运行开始，单件操作间的等待也计入 180 秒。实际比赛启动方式需与 STM32 的启动按钮事件联调，目前界面按钮用于开发。

## 日志与恢复

每次完成一件，将任务编号、会话、类别、盒号、位置和是否模拟写入 `logs/round_*.jsonl`。通信报文显示在界面，便于串口联调。未知落料结果不增加成功数量。

重新连接、程序重启后的自动任务恢复尚未实现。遇到结果未知、断线或复位，应先核对物体和盒中内容，再开始新一轮；不要只点回原点就假定盒子为空。当前计数和盒号映射在本次程序运行中维护，日志供人工核对。

## 当前验证

开发环境：Windows、Python 3.14、OpenCV 5、NumPy 2.4、pyserial 3.5。九项测试覆盖完整 12 件演示、CRC 与流解析、丢包去重、丢失结果查询、停止、复位识别、落料失败不计数和标定。真实相机、真实串口及香橙派环境仍需现场联调。

依赖 API 参考：[pySerial](https://pyserial.readthedocs.io/en/latest/pyserial_api.html)、[OpenCV 标定与坐标转换](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)。
