# 视觉、遮挡、抓取与二维码：一手资料研究笔记

研究日期：2026-11-04（Asia/Singapore）。本文件为方案设计依据，不代表已在 Orange Pi 或实物上验证。参数建议均为本项目的工程起点，不是论文保证值。

2026-11-08归档提示：实际设备和视觉分支已确认的八类形状、单层优先及双相机条件，参见[主报告归档说明](../vision-system-options-2026-11-04.md)；本笔记保留11月4日的候选研究。

## 1. 与当前机构对应的边界

仓库 `ai-dialogue/README.md` 当前记录是 X/Y 42 步进电机、Z MG90S 舵机、DS3120 六槽转盘，机构执行拨料。以下“夹爪抓取”研究仅用于用户确有夹爪/机械臂后的条件分支；不能把二维拨料机构解释成已具备六自由度抓取能力。现阶段可共享检测、定位、物块优先级、碰撞检测和动作后重识别；动作生成器应区分 `push` 与 `grasp`。

## 2. 分割究竟增加了什么，不能解决什么

普通检测提供类别、置信度、轴对齐框；实例分割额外给出每个实例的像素轮廓。Ultralytics 的分割数据按一个实例一行、多边形坐标表示；这种输出本身不是深度、承重关系或机器人动作。[Ultralytics 分割格式](https://docs.ultralytics.com/datasets/segment/)

据此对本项目的工程推论：

- 可计算可见区域面积、轮廓方向、距离变换最大内接点、邻物间隙；比直接用 bbox 中心更能避免落点位于背景或邻物上。
- 可见掩膜的质心不等于完整物块质心、质量中心或可夹持中心。被遮挡的半块尤其容易偏移。
- “掩膜面积 / 框面积”是形状填充率，不是可靠遮挡率。真实可见率 `A_visible / A_full_projected` 需要完整形状、姿态、已知尺寸模板或额外的 amodal 模型；缺少分母时存 `visibility=unknown`，不能伪造测量值。
- 两个二维框相交不证明两块接触、压住或叠放。轮廓 T 形交汇、边缘截断、阴影等只能作为有置信度的线索；普通 RGB 不应由这些线索独立批准高风险抽取。
- “最高表面”需要已标定深度或可靠几何估计；“上方没有障碍”还需要手指、挡板及整个进入路径的空间检查。物体最高点高，不保证目标没有被邻物压住。
- 完全遮挡时没有可直接检测的像素。即便根据已知物块总数推断还有剩余，也只能标记“库存未完成”，不能生成该物块的精确抓取位置。

最低可行闭环是一次选择一个物块，执行后让机构退回观察位置，再拍新图。轻微遮挡可依可见特征检测；严重遮挡优先操作更暴露、路径已知的邻物；完全遮挡依靠移开遮挡物或换视角，不能靠换一个 YOLO 保证解决。

## 3. 深度、点云与学习式抓取

### 3.1 RGB-D + 几何候选，比直接上点云大模型更适合首个三维版本

建议完整流程：同步 RGB/Depth → RGB 检测或分割 → 深度对齐 → 掩膜内有效深度过滤 → 反投影及机器人坐标转换 → 托盘平面去除 → 物块表面/高度估计 → 顶部或侧边候选动作 → 工具体积与进入路径检查 → 执行 → 重拍。

相机 Z 深度值为 `d`、畸变已校正时：

```text
p_camera = d * K^-1 * [u, v, 1]^T
p_base = R_base_camera * p_camera + t_base_camera
height = n_tray^T * p_base + b_tray
```

其中深度单位必须一致，`d` 不一定是沿射线的欧氏距离，按 SDK 定义处理；`K` 必须匹配 RGB/Depth 对齐后的图像尺寸。针孔模型和内外参定义依据 [OpenCV calib3d](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)。

工程注意：用掩膜腐蚀后内部有效点统计高度，避开轮廓“飞点”；拟合平面或稳健分位数比单像素深度可靠。不要对无深度的黑色、反光表面直接填入平均高度后执行。RealSense 官方说明立体匹配依赖纹理，低纹理表面和反光会造成孔洞、错误深度；投影纹理和滤波有帮助但不是通用修复。[RealSense 深度后处理](https://dev.realsenseai.com/docs/depth-post-processing-for-intel-realsense-depth-camera-d400-series/)

`height_confidence` 与“类别置信度”应分字段存储。深度不可靠可退回二维简单场景规则、换角度或跳过目标。深度相机最小工作距离、视场、USB 带宽、ARM64 SDK、黑色材料表现都须以选定型号实测。

### 3.2 GG-CNN：有夹爪和深度后可试的轻量学习式方案

作者实现输入深度图，为像素输出抓取质量、平面方向及夹爪宽度；仓库包含 GG-CNN/GG-CNN2，支持 Cornell 与 Jacquard，示例模型含卷积和转置卷积。原代码环境较旧，不能假定直接兼容当前 PyTorch/RKNN。[作者代码](https://github.com/dougsm/ggcnn)

完整方案可用 YOLO 负责比赛类别，GG-CNN 负责深度图上的候选抓取；将候选中心关联到目标掩膜，再做三维碰撞、宽度、可达性检查：

```text
g = (u, v, theta, width, quality)
accept(g, i) = center_in_mask(g, i)
               AND width_in_gripper_range(g)
               AND depth_valid(g)
               AND approach_volume_free(g)
               AND robot_reachable(g)
score(g, i) = priority(i) + a*quality(g) + b*class_conf(i)
              + c*clearance(g) - d*move_cost(g) - e*uncertainty(g)
```

原论文报告了其研究系统的闭环能力；不能把其 50 Hz 或成功率迁移为 Orange Pi 指标。[原论文](https://arxiv.org/abs/1804.05172)

建议仅先做离线导出和固定输入的 RKNN 转换试验，逐层核对转置卷积、尺寸及输出。未找到经过本次核验的官方 RK3588 GG-CNN 端到端基准，不能保证 NPU 兼容或速度。它预测的是候选质量，依然不知道比赛优先级，也不替代机械动作验证。

### 3.3 GraspNet：研究分支，现机构不应作为必需组件

GraspNet-1Billion 提供 RGB-D、实例掩膜和六自由度抓取等标注，官方项目说明含 190 个场景、97,280 张图、88 类物体及大量抓取姿态。[GraspNet 项目](https://graspnet.net/)

官方 baseline 安装要求编译 PointNet2 算子，实验后处理还进行单视角点云碰撞检测。[GraspNet baseline](https://github.com/graspnet/graspnet-baseline)

工程推论：普通 ONNX→RKNN 不能自动替代这些点云采样/分组等自定义算子。现阶段可在 RTX/AutoDL 上评估其对真实堆叠的收益，或用其结果辅助验证简单几何算法；如果最终必须单机 Orange Pi 推理，就应先证明部署链，不能让这种模型成为初赛主路径。单视角点云看不见背面空域，未知体素不能当作已确认空闲。真实末端执行器也需满足模型使用的夹爪结构、宽度和自由度。

## 4. 多视角：增加信息，不是无条件恢复三维

完整方案可采用顶视 RGB + 固定侧视 RGB：两相机标定 → 同步或在静止场景采图 → 各视角 YOLO/分割 → 按类别、外观和几何约束关联 → 得到可见区域及遮挡证据 → 有足够对应点才三角化 → 合并候选与冲突 → 动作 → 重识别。固定双相机比为初赛新造运动相机机构简单。

若可控制相机/机械臂视角，可在不确定时从少数预定安全观察位中选择下一视角：

```text
v* = argmax_v [expected_information_gain(v)
              + lambda*expected_visible_target_area(v)
              - mu*view_change_time(v)]
```

这里信息增益应先用可实现的代理，如已知遮挡方向与可见掩膜变化，不必初赛实现复杂神经渲染。Morrison 等人的 Multi-View Picking 正是通过主动选视角降低杂乱和遮挡造成的抓取不确定性，但其论文系统性能不是本板的保证。[原论文](https://arxiv.org/abs/1809.08564)

实用约束：

- 第二视角可以看见原视角背面的物块；如果所有视角都不可见，仍需物理移除遮挡物。
- 相同、无纹理物块的跨视角身份匹配很难，不能仅凭检测框中心进行立体三角化。
- 被操作后的物块位置可能变化，必须更新场景版本；旧视角几何不能与新场景混合。
- 双目三角化需要内外参、可靠对应点及基线；单目深度预测常有尺度/域偏差，未经现场标定不作为毫米级运动指令。
- 对当前 L 挡板，可先把多视角用于判定挡板是否退离、目标哪侧暴露，以及选择低风险拨料方向，而不必完整三维重建。

## 5. SAM 3 的合理位置

2026-11-04 核验的官方 README 描述 SAM 3 可由文本、点、框或掩膜提示进行检测、分割、跟踪；模型为 848M 参数，官方安装前提列出 Python ≥3.12、PyTorch ≥2.7、CUDA ≥12.6，并已列有 SAM 3.1 更新。[Meta 官方仓库](https://github.com/facebookresearch/sam3)

本项目建议是 RTX 5060 或 AutoDL 上辅助标注、生成候选掩膜、查漏与难例分析，之后人工修正并训练轻量模型。这里没有测量 5060 显存占用，不保证特定批大小或训练配置。使用权重还须遵循官方获取流程。

本次没有找到并验证可作为比赛基线的官方 SAM 3→RKNN/RK3588S 部署链。其模型规模、Transformer 结构和官方 CUDA 路径使板端工作量显著高于轻量 YOLO；这是工程判断，不等同于断言“数学上不可能转”。它也不直接输出运动坐标、支撑关系、二维码内容或成功抓取证明。可用离线 SAM 辅助数据生产，不必为此改动在线动作接口。

## 6. 二维码：预留接口，初赛关闭

OpenCV 官方 API 明确区分 `detect`（返回四边形）与 `decode`（解码），也提供多码与组合调用。[OpenCV GraphicalCodeDetector](https://docs.opencv.org/4.x/d7/d90/classcv_1_1GraphicalCodeDetector.html)

| 路径 | 适用点 | 主要限制与建议 |
| --- | --- | --- |
| OpenCV QRCodeDetector | 已有 OpenCV 依赖时接入成本低，可直接尝试静止原图或 ROI | 直接检测失败不代表没有二维码；解码空字符串不等于物块类别未知 |
| ZXing-cpp | C++ 核心、Python 包；可作为另一解码后端 | 对 ARM64/Linux 有现成 wheel，但需匹配 Python、ABI、glibc；无 wheel 时需 C++20 构建环境 |
| YOLO 检测 QR 区域，再裁剪解码 | 复杂背景、已知物块位置、码区定位需要学习时有价值 | YOLO 只找到区域；应裁原始高分辨率图，保留留白，并校正四角；不能从已缩小的640输入恢复细节 |
| 把“带码物块”设独立类别 | 若规则只要求区分带码/不带码，可快速实现 | 不能输出内容；码面不可见时标签有歧义；更推荐物块类别 + `qr_present` 属性，避免类别乘法爆炸 |
| 多帧/多角度 | 选择静止、清晰帧，或侧面码需要换视角 | 使用有界重试；融合相同目标上已校验的完整 payload，不拼接不同物块或凭空补内容 |

ZXing-cpp 官方 Python 绑定可接 OpenCV/NumPy 图像；当前 PyPI 3.1.1 提供 Linux aarch64 wheel，是否能直接安装仍要看板上系统。[官方 Python 包说明](https://github.com/zxing-cpp/zxing-cpp/blob/master/wrappers/python/README.md)、[维护者发布的 PyPI 文件](https://pypi.org/project/zxing-cpp/)

以下鲁棒性判断属于成像和系统工程推论，没有在本场景实测解码率排名：

- 小码：先提高原始采集分辨率或近距离拍摄；ROI 放大可帮助算法采样但不能恢复不存在的模块细节。不要宣传某一解码器必胜。
- 倾斜：检测四角并透视校正；仅 OBB 的平面旋转不足以修正透视压缩。
- 部分遮挡/污渍：可尝试纠错，但定位图案或关键信息破坏时仍会失败；改视角/移开邻物通常更有效。
- 光照不均：补充漫射照明、锁定合理曝光；灰度、CLAHE、自适应阈值可作有限候选，需选验证集防止伪影。
- 运动模糊：优先静止后拍摄、缩短曝光和增加光照；盲目多帧平均会保留或加重模糊。
- 纠错率不是可任意遮住的面积百分比。DENSO WAVE 将纠错能力定义为码字比例，不保证遮挡同等比例图像仍可读。[DENSO WAVE 纠错说明](https://www.qrcode.com/en/about/error_correction.html)

预留的概念接口：

```python
QRCodeResult = {
    "enabled": False,
    "mode": "off",       # off / presence / payload，规则明确后切换
    "object_id": None,
    "scene_id": None,
    "detected": None,     # None = 未运行或证据不足，不是 False
    "quad_px": None,
    "decoded": False,
    "payload": None,
    "decoder": None,
    "attempts": 0,
    "reason": "disabled",
}
```

初赛 `off` 不加载解码器、不阻塞动作。决赛若只看有无码启用 `presence`；若要内容启用 `payload`，解析规则由独立模块处理。性能分别报告 QR 区域检测召回率、检测到区域后的解码成功率、正确 payload 的端到端成功率、耗时和有界重试次数。

## 7. 初始数据和标注建议

以下数量是本项目的采集预算，不是文献给出的充分性定理：从 1,200–2,000 张真正不同的现场 RGB 图开始，优先多场景而非连续视频近重复；每类争取 150–300 个多角度可辨实例，类别较多时增加总量。第一批可先用 300–500 张验证采集/训练/导出链，再按误检漏检补数据。

建议场景配额：单独/疏松 40%，轻微重叠或紧密接触 30%，明显堆叠 20%，空托盘/挡板/手和阴影等负样本 10%。比例应按实际初赛分布调整，难例单列测试集，避免过多极端图损伤主分布。采集至少多次拆摆、不同光照时段、托盘位置和背景、真实相机高度/焦距；物块外观、污渍、二维码变化由规则决定。

标注约定需先写清：

- 检测：类别 + 本项目统一的可见实例外接框；部分遮挡但身份明确仍标注，严重到身份不明的用难例标记/单独审查，避免猜类别。不要一部分标可见框、一部分想象完整框。
- 分割：标可见像素，不“补画”遮挡后部。保持同一实例的碎片身份；源数据优先保留支持多连通区域的掩膜/COCO RLE。导出 YOLO 多边形后检查栅格化效果，不能因格式连接碎片而把桥接像素当真实可抓区域。
- 完全不可见物块不添加视觉实例标签；已知库存单独记录，不能把无像素物块当检测真值。
- OBB：只有形状方向影响拨料/夹持时才值得标注；正方形、圆形具有对称性，角度评价应考虑等价角。OBB 不是三维姿态。
- 抓取点：只有实施学习式夹爪模型才补充中心、夹爪方向/宽度、深度/接近方向、成功失败记录；单个“中心点”标签不能表示所有可执行抓取。
- 若学习挡板拨料策略，必须用动作、动作前后图像和结果数据，不可拿平行夹爪的成功标签直接训练拨料成功率。

可用 COCO 预训练轻量检测/分割骨干，再对比赛类别微调；公开数据不能替代现场。学习式抓取可利用 Cornell/Jacquard/GraspNet 做预训练或算法对照；抓取数据的工具、深度噪声、物体材质和任务与本项目有域差异。GG-CNN 作者仓库提供 Cornell 预训练示例；Jacquard 全量数据有访问申请流程，不能假定可立即下载。[GG-CNN 数据说明](https://github.com/dougsm/ggcnn)、[Jacquard 官方站](https://jacquard.liris.cnrs.fr/)

增强以真实摄像头变化为边界：亮度/对比度/适度色彩变化、旋转、平移、尺度、轻微透视、轻度模糊/噪声、局部污渍/遮挡、合理 Copy-Paste。若颜色本身是类别，不可大幅改 hue；若需读 QR，不可把增强后的变形图当可正确解码真值；RGB-D 增强必须同步更新深度和几何标签。Ultralytics 提供 Mosaic、MixUp、Copy-Paste 等配置，具体功能依训练版本固定。[官方增强说明](https://docs.ultralytics.com/guides/yolo-data-augmentation/)

按采集批次/拆摆场景划分 train/val/test，例如 70/15/15，禁止相邻视频帧随机分进不同集合；留一批新物块摆放和灯光作为最终盲测。训练验证除检测/分割指标外还要测：类别混淆、定位毫米误差、候选动作可行率、实际执行成功率、动作后误判完成率。模型评估和整机验证要分别记录。
