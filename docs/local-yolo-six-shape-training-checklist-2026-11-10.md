# 六形状 YOLO 本地训练任务清单

状态：执行清单；截至 2026-11-11，**本轮尚未用正式相机采集数据、标注或训练**。目标是用 Windows 电脑得到能识别六种形状的普通 YOLO 检测模型 `best.pt`，并在未参加训练的新照片上本地推理、记录测试结果。本阶段不要求 Orange Pi 5 Plus、STM32、拨料或 RKNN。六色识别是后续在检测框内运行的传统视觉模块，不属于这份 YOLO 权重的六个类别。

本文件是 2026-11-10 的阶段性清单。当前已完成 698 张数据的正式训练，最新代码、数据和结果见[中期视觉资料](../midterm-vision/README.md)；以下未完成项保留为当时的计划记录。

六类固定为 `cube` 正方体、`sph` 球体、`cyl` 圆柱体、`tpri` 三棱柱、`cone` 圆锥体、`tet` 四面体；ID 按[实施方案](midterm-yolo-shape-color-plan-2026-11-10.md)中的 0–5 顺序。旧的三类积木公开数据集只适合练习工具操作，不作为本项目六类训练数据。

## 一个目标，三个可检查的结果

**目标：** 做出可在电脑本地运行的六形状 YOLO 检测模型。

1. **数据就绪：** 有正式机位的原始照片、六类矩形框标签、独立的训练/验证/测试划分；能说清每类有多少标注实例，测试图没有与训练图近重复。
2. **模型就绪：** 本机训练得到可重新加载的 `best.pt`；保存数据版本、六类顺序、训练参数、软件环境和模型文件。
3. **效果可说明：** 在留出的测试集和新摆放照片上运行，报告每类漏检/误检与混淆，保存成功和失败的预测图。测试表现以实测数字为准。

## 按顺序做什么

### 1. 固定拍摄条件

- [ ] 用**最终准备使用的相机**固定机位，保证托盘工作区完整入镜，并能看到六种形状的关键侧面/棱边。先各拍几张试图；若人看图也分不清球、圆柱和圆锥，先改机位。
- [ ] 用队友现有灯带做灯开/关对比，选阴影、反光较少且稳定的布置；固定灯、相机分辨率、曝光和白平衡。
- [ ] 拍几张空盘，以及每种形状单独放在托盘中心和边缘的照片，检查是否虚焦、太小、被机构挡住。

**你交给训练环节：** 固定机位的试拍图、相机/灯光设置、六种实物是否都看得清的判断。此前手机模拟视角照片只用于选机位，不直接充当正式相机测试。

### 2. 拍自己的数据集

- [ ] 每次**重新摆放**后拍照，覆盖六类、不同位置/旋转、单件与稀疏多件、少量相邻或轻遮挡，以及空盘。不要从一段静止视频里截大量近重复帧凑数。
- [ ] 尽量让同一形状出现多种颜色、同一颜色出现在多种形状中，避免模型把颜色当成形状的捷径。记录现有实物做不到的组合。
- [ ] **先拍 60–100 张真正不同的场景**，覆盖六类，用作首轮精标与短训练；每类先争取约 15–30 个可辨认实例。这是启动量，不代表模型已足够好。保留独立验证/测试场景。
- [ ] 初版模型出来后，再按实际漏检/混淆补拍约 100–200 张有针对性的场景；如果已有模型在新摆放上表现够用，可以停止补拍。**800 张不是必须拍或必须标的数量**。照片数和框实例数分别统计。
- [ ] 保留原图，按日期/拍摄批次编号；另记每张的实物、形状、颜色、灯光和摆放情况。

**你交给标注环节：** 原始照片和拍摄批次表。原图不覆盖、不直接用增强图代替。

### 3. 标注六种形状

- [ ] 首批推荐用 [AnyLabeling Windows 版](https://anylabeling.nrl.ai/docs/installation)本地标注。手动拖框用 CPU 版即可，和稍后训练模型的 GPU 环境分开。打开照片文件夹，选 **Rectangle/矩形框**，对每个可辨物体拖框并选一个形状类别，保存后切下一张。**不需要手写坐标文件，也不用画多边形掩码**。
- [ ] 在标注工具里建立上述六个固定类别。每张图的每个**可辨认物体**都画一个可见部分的外接矩形框，不能只标最显眼的一件。
- [ ] 先人工精标首批 60–100 张。若按形状分批拍单物体、背景稳定，可用空托盘差分自动给候选框、按拍摄批次给候选类别；仍要逐张核对。多物体照片优先手工标首批。
- [ ] 用首批数据训出初版后，让模型为新增照片**预画框和类别**，人在标注工具中逐张纠正漏框、框合并、错类、遮挡处理不一致。预标注能省从零画框的时间，但不能把未核对的预测直接当真值。[Ultralytics 辅助标注](https://docs.ultralytics.com/platform/data/annotation/)、[CVAT 自动标注](https://docs.cvat.ai/docs/annotation/auto-annotation/ai-models/)
- [ ] 优先补标模型看错、没看见、低把握以及代表新位置/姿态的照片；剔除大量近重复画面。无法从图中判清形状的照片放审核集。
- [ ] 导出 YOLO **目标检测**格式，检查 `data.yaml` 的类别顺序、图片/标签对应关系和空盘标签。格式是一物一行、类别 ID 加归一化框坐标。[Ultralytics 数据格式](https://docs.ultralytics.com/datasets/detect/)
- [ ] AnyLabeling 中走 **Tools → Export Annotations → YOLO**，导出后会有每张图对应的 `.txt` 和类别表；训练前仍需检查/生成匹配的 `data.yaml`，不要把工具的原生标注文件直接当 YOLO 训练标签。[AnyLabeling 导出说明](https://anylabeling.nrl.ai/docs/data-exporting)
- [ ] 至少抽查每类的单件、边缘、接触、暗面样本，把标签画回原图确认。

**完成标志：** 类别数、每类实例数、漏标与错标抽查结果可列出来。

### 4. 划分数据并留盲测

- [ ] 按**重新摆放批次**分训练、验证、测试，可先用约 70/15/15；相邻视频帧和同一摆放的多张照片必须在同一组。
- [ ] 再留一批模型完成后才拍的“新摆放”照片。建议测试中每形状至少争取 20 个独立摆放实例；不足时如实写出分母。
- [ ] 测试集留到选定模型后做最终评估，不拿它反复改标注、调训练参数。

**完成标志：** 能看到 train/val/test 图片和标签数量、每类实例数，以及分组规则。

### 5. 在 Windows 电脑搭训练环境

- [x] 已在本机只读核对：RTX 5060 Laptop GPU（8151 MiB 显存）、驱动 582.05；默认 Python 3.14.2，另有可执行的 Python 3.12.13。默认 Python 的 PyTorch 为 `2.14.0+cpu`、`torch.cuda.is_available() == False`，未安装 Ultralytics；Python 3.12.13 尚无 PyTorch/Ultralytics。因此**目前不能直接用默认 Python 做 GPU 训练**。
- [ ] 为本任务创建独立虚拟环境，优先评估现有 Python 3.12.13 与官方 Windows CUDA 版 PyTorch 的兼容性；按[PyTorch 官方安装页](https://pytorch.org/get-started/locally/)选择适配的安装组合，不把已有 CPU 版当 GPU 版。
- [ ] 安装与本机显卡兼容的 PyTorch、Ultralytics，确认 PyTorch 能实际使用 GPU；记录版本。环境安装命令以实测系统情况决定，不照搬旧教程。
- [ ] 用少量本项目数据和预训练 `yolov8n.pt` 跑 **3–5 轮短训练**，确认标签、类别顺序、显存和输出目录正常。短跑只查链路，不当最终结果。[Ultralytics 训练说明](https://docs.ultralytics.com/modes/train/)

**完成标志：** 短跑无数据/显存错误，能找到输出权重和几张可视化预测。

### 6. 正式训练与只改有证据的问题

- [ ] 从预训练 `yolov8n.pt` 开始六类微调。`imgsz=640` 可作第一轮起点；轮数、batch 和早停按显存及验证曲线调整，不预设“训练越久越好”。
- [ ] 保存 `best.pt`、训练曲线、类别配置、数据版本、运行参数、开始/结束时间与环境版本。不要只保留权重而丢失它对应的类别顺序。
- [ ] 看验证集的逐类漏检、误检和混淆，再决定下一轮只优先改一个主要问题：补某类/某角度照片、纠正标签、改机位，或调整训练设置。不要连续无记录地换模型和参数。

**完成标志：** `best.pt` 可以在本机重新加载并对原图输出六类框。

### 7. 独立测试与本地演示

- [ ] 用冻结的 `best.pt` 对 test 划分评估，记录每类 precision/recall、mAP、混淆与失败图；测试报告注明图数和每类实例数。[Ultralytics 验证模式](https://docs.ultralytics.com/modes/val/)
- [ ] 用新摆放、未训练也未调参的照片在电脑上推理；展示原图、预测框、类别和置信信息。可再试本地摄像头实时画面，但照片推理通过即可满足本阶段的模型交付。
- [ ] 单独查看球/圆柱/圆锥、三棱柱/四面体以及暗面、接触场景，把失败类型列出。若改进了模型，保留旧版结果与新版对比。

**最终交付：** `best.pt`、六类名称/顺序、测试指标表、若干成功与失败的预测图、简短训练记录；能在 Windows 本机重复打开模型并推理新照片。

## 你需要亲自完成的部分

固定相机和灯、准备六种实物、重新摆放拍摄真实照片、核对每张物体的真实类别，以及判断实际照片是否满足演示场景。训练环境检查、标签格式检查、训练命令、结果分析和本地推理程序可在取得数据后由 AI 协助推进；关键的**实物类别真值和机位选择**必须以你的现场观察为准。

## 这次先停在什么边界

拿到 `best.pt` 后已完成的是**六形状 YOLO 模型**。若中期展示还要求六种颜色，再另做原图检测框内的前景掩码＋HSV 颜色模块，并独立验证；颜色不会因为六形状权重训练完成而自动出现。Orange Pi 部署与拨料联动属于之后的独立工作。
